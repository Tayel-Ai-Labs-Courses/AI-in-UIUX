# Rubric — 100 points

| # | Criterion | Points |
|---|---|---|
| 1 | Research & problem definition | 15 |
| 2 | Information architecture & flows | 15 |
| 3 | Visual design & design system | 20 |
| 4 | Interaction & prototype | 15 |
| 5 | States, edge cases & accessibility | 15 |
| 6 | Rationale & communication | 20 |

Note where the weight sits: **rationale is the single largest block**, and
together with states and accessibility it outweighs visual design. This is
deliberate. Anyone can make one pretty screen. The job is everything around it.

---

## 1. Research & problem definition — 15

| | |
|---|---|
| 13–15 | A specific user, a real journey, findings that are actually findings. Later design decisions clearly trace back here. |
| 9–12 | Solid research, but it sits in its own folder and never influences the design. |
| 5–8 | Generic persona, stock journey, teardown that only describes. |
| 0–4 | Missing, or copied. |

## 2. Information architecture & flows — 15

| | |
|---|---|
| 13–15 | Structure is obvious without explanation. Two wireframe options genuinely compared. |
| 9–12 | Reasonable structure; the comparison is thin or missing. |
| 5–8 | Screens exist but the relationships between them don't. |
| 0–4 | No IA work. |

## 3. Visual design & design system — 20

| | |
|---|---|
| 17–20 | A system, not a set of screens. Tokens named, components reused, spacing on a scale. |
| 12–16 | Good-looking and mostly consistent; the system is implied rather than documented. |
| 7–11 | Screens drawn one at a time. Spacing and type drift between them. |
| 0–6 | Incoherent or incomplete. |

## 4. Interaction & prototype — 15

| | |
|---|---|
| 13–15 | The flow clicks through end to end and feels considered. Transitions have a reason. |
| 9–12 | Works, with dead ends or a few unlinked hotspots. |
| 5–8 | A few screens linked; no coherent flow. |
| 0–4 | No prototype, or the link is dead. |

## 5. States, edge cases & accessibility — 15

| | |
|---|---|
| 13–15 | Empty / loading / error designed everywhere. Contrast passes. Meaning never carried by colour alone. Mobile genuinely designed, not squeezed. |
| 9–12 | Most states present; accessibility partly addressed. |
| 5–8 | Happy path only. |
| 0–4 | Not considered. |

## 6. Rationale & communication — 20

| | |
|---|---|
| 17–20 | Every significant decision explained, including what was rejected. READMEs are readable and honest about trade-offs. |
| 12–16 | Decisions explained, but only the ones that worked out. |
| 7–11 | Descriptions of what is on screen, not why. |
| 0–6 | Images with no words. |

---

## Automatic deductions

| | |
|---|---|
| −10 | Dead or permission-locked Figma link. |
| −10 | A required screen missing. |
| −5 | Files dumped outside the template structure. |
| −5 | Per day late. |
| Fail | Work that is not yours, presented as yours. Using a template or a UI kit is fine and encouraged — **say so** in your README. |

## Bonus — up to 10

- A working Arabic RTL version, properly mirrored (+5)
- Both light and dark themes, tokenised (+3)
- Motion spec — real durations and easing curves, not "it fades" (+2)
- Any usability test with a real human, documented honestly, including what
  went wrong (+5)

Bonus is capped at 10 and cannot raise a score above 100.
